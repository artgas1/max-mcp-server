# Протокол MAX: что проверить на живом аккаунте

Статус: **не проверено**. В треде 2 по условиям заказчика не было ни входа в реальный аккаунт, ни
запросов к серверам MAX. Всё ниже — предположения по исходникам PyMax 2.5.0 и web-клиенту; в коде для
каждого пункта есть безопасный фолбэк. Проверку делает заказчик после своего входа
(`max-mcp login qr`), только чтение, с `MAX_LOG_LEVEL=INFO` (сырые коды ошибок пишутся в stderr строкой
`MAX ApiError opcode=… error=… title=…`, без payload).

Сюда записывать только обезличенные факты: коды, имена полей, хосты. Никаких телефонов, токенов, имён,
названий чатов.

## 1. Ошибки

| что | как сейчас в коде | что проверить |
|---|---|---|
| истёкшая/отозванная сессия | `ApiError` на `LOGIN` с `FAIL_LOGIN_TOKEN` / `FAIL_LOGOUT_ALL` → `SessionExpired`, переподключение прекращается | завершить сеанс устройства с телефона → какой `error` приходит: на `LOGIN` при переподключении или в ответ на обычный запрос (тогда добавить его код в `is_session_revoked`) |
| флуд | регэксп `flood\|too.?many\|limit\|rate` по `error`/`title` → `RateLimited` | серия быстрых `CHAT_HISTORY` (например, `max_chat_timeline` по большому чату с `MAX_RPS=50`) → реальный код и есть ли `retry_after`/время ожидания в payload |
| нет доступа / не найдено | регэкспы `access\|denied\|forbidden…` и `not.?found…` | запрос к чужому/удалённому чату, к несуществующему сообщению |
| всё прочее | `UpstreamError("MAX вернул ошибку (<code>)")` — только код, без текста сервера | собрать встречающиеся коды |

## 2. Скачивание медиа (allowlist хостов)

`https`, без редиректов (`allow_redirects=False`), лимит по потоку.

Проверить:
- реальные хосты `PhotoAttachment.base_url`, `AudioAttachment.url`, `FILE_DOWNLOAD`(88) → `url`,
  `VIDEO_PLAY`(83) → `url` / поля в `model_extra` (качества видео);
- нужны ли к `base_url` фото параметры размера (сейчас качается как есть);
- бывают ли редиректы (если да — тред 3 делает ручной проход с повторной проверкой хоста);
- что означает `FileRequest.unsafe=true` (сейчас только пишем в лог).

## 4. Поведение, от которого зависит корректность

- `CHAT_HISTORY`: включает ли ответ сообщение с временем, ровно равным `from`, в `backward` и/или
  `forward` (код устойчив к обоим вариантам: граница по ключу `(time, id)` + дедупликация).
- `CHAT_HISTORY` с `forward>0` от раннего `from` (чтение периода по возрастанию): работает ли от `from=1`
  (у PyMax `from=0` превращается в «сейчас», поэтому шлём `max(1, from)`).
- `fetch_comments(from_=…)`: `from_` — это время (мс) или id комментария? Сейчас передаём время.
  Порядок и перекрытие страниц комментариев.
- `CHATS_LIST`: размер страницы и включается ли чат с `last_event_time == marker` (дубли не страшны,
  пропуски — проверить на аккаунте с > 200 чатов).
- Пинг с `interactive=false` (`MAX_APPEAR_ONLINE=false`): держится ли соединение часами; не показывается
  ли «в сети» собеседникам.
- `Chat.new_messages` — актуален ли без `CHAT_MARK`; не сбрасывается ли непрочитанное от
  `CHAT_HISTORY(interactive=false)` (проверить: `max_unread_summary` дважды подряд → счётчики те же,
  на телефоне сообщения остаются непрочитанными).
- События: приходит ли `chat_id` в `NOTIF_MESSAGE` у web-клиента (PyMax FAQ: бывает `None`).
- Где в `AudioAttachment` текст расшифровки (сейчас ищем `transcription`/`transcriptionText`/`text` в
  `model_extra`).
- Признак «чат заглушён» (mute) в `Chat.options` — нужен для фильтра `include_muted` в
  `max_unread_summary` (пока параметра нет).
- Длительность `VIDEO`/`AUDIO`: секунды или мс (сейчас: > 1000 считаем мс).
- `Presence.seen`: секунды или мс.

## 5. Запись (тред 3) — проверить на тестовом чате

Только в своём тестовом чате/группе, с `MAX_READ_ONLY=false MAX_WRITE_CHATS=<id тестового чата>`.

| что | как сейчас в коде | что проверить |
|---|---|---|
| ответ `MSG_SEND` | `Message.model_validate(payload)` (PyMax разворачивает `{"message": …}`) | что приходит `id`, `chatId` (если нет — подставляем свой) |
| `markdown=false` | `elements: []`, текст как есть | что `*`, `_`, `` ` `` отображаются буквально |
| пересылка | `link.messageId` числом (PyMax шлёт строкой → «Expected number») | что работает и что возвращается (`link.message` с исходным текстом) |
| опрос | `settings`: 4 (REVOTE) или 0 | что 0 принимается (или нужен иной флаг по умолчанию) |
| `remove_users_from_group` | `clean_msg_period=0` | не удаляет ли 0 сообщения участника |
| `join_channel` | для `https://max.ru/<ник>` | принимает ли сервер полный URL публичного канала |
| флуд при отправке | `MAX_SEND_LIMIT` 5/мин, 20/ч | реальные лимиты MAX и код ошибки |
